# TanStack Start template

The base template every generated project starts from, and the source repo the Modal sandbox
image is built from (`plans/01-sandbox-modal.md`, `plans/09-template-and-assets.md` in the main
app's monorepo). Public by design (D9) — this is exactly the code a user's project starts as, and
exactly what an exported project looks like unmodified.

## Stack

- **TanStack Start** (Vite, SSR streaming, no RSC) + **TanStack Router** (file-based routes)
- **TanStack Query**, wired through the router via `setupRouterSsrQueryIntegration`
- **Tailwind v4** (CSS-first tokens, `src/styles/app.css`) + **shadcn/ui** on **Base UI**
  (`style: base-nova`, `rsc: false`) — not Radix. Base UI's composition prop is `render`, not
  `asChild`; keep that in mind when wiring a `ui/` primitive to a router `<Link>` or similar.
- **motion**, **react-hook-form** + **zod** + **@hookform/resolvers**, **lucide-react**,
  **recharts**, **@tanstack/react-query** — pre-installed and ready, even though the template's
  own pages don't exercise all of them (see "What's intentionally minimal" below)
- Toasts use shadcn's **Base UI-native `toast`** component (`@base-ui/react/toast`), not `sonner`
  — no extra toast library and no `next-themes` dependency to fight with
- ESLint (flat config) + Prettier, TypeScript strict

## Structure

```
src/
  routes/          index.tsx and __root.tsx only — a blank page, nothing else
  components/
    ui/            shadcn on Base UI (50 primitives)
    kit/           page sections: Navbar, HeroCentered/HeroSplit, FeatureGrid/FeatureRows, Stats,
                   LogoCloud, Pricing, Testimonials, FAQ, CTA, Footer, ContactForm, plus Container,
                   Section, Photo, Reveal/Enter, and the route error/not-found/pending screens
    fx/            78 effect and UI components adapted from Magic UI (see NOTICE)
    CATALOGUE.md   generated index of kit/ and fx/, and the font pairings (the agent reads this)
  lib/             utils (cn), seo (head helper), use-theme, css-color, theme-script, constants
  styles/          app.css (design tokens, light + dark), kit.css (keyframes for fx/)
public/            favicon.svg, og.png (default share picture), robots.txt
```

`src/routeTree.gen.ts` is generated by the TanStack Start Vite plugin on `dev`/`build`. It is
gitignored and must never be hand-edited or committed.

## The kit

The template ships its own component library so a generated project starts from good parts
instead of writing every section and effect from scratch.

- **Tokens only.** Every component takes its colours from the tokens in `app.css` (`bg-background`,
  `text-primary-foreground`, `bg-scrim` over photos, `--chart-1..5` for accents). A project changes
  its look by editing the token values; the whole kit follows, including dark mode. ESLint rejects
  literal colours (`text-white`, `bg-[#fff]`, hex strings, SVG `fill="#..."`) under
  `src/components` and `src/routes`, so this stays true.
- **Server-render safe.** `Reveal` is visible in the server HTML and only hides content below the
  fold after hydration; `Enter` is CSS-only. Neither can leave a page blank if scripts are slow.
- **Catalogue.** `src/components/CATALOGUE.md` is generated from the `@kit` header at the top of
  each component (`npm run catalogue`; `npm run catalogue:check` runs in CI). The header holds what
  the component is for, its props and a usage example.
- **Fonts** are self-hosted through Fontsource (24 families installed, pairings in the catalogue).
- The Router and Query devtools are not mounted: they put badges on every preview and screenshot,
  and the Router devtools throw for some route setups.

## What's intentionally minimal

This template ships **one route** (`index.tsx`) that renders a blank page: no nav, no hero, no
footer, no sample content. A generated project's first prompt should build the page from nothing,
not strip out example content first. The components in `kit/` and `fx/` are parts to build with,
not a page; nothing in them appears on a route until it is imported.

## Design tokens

Every color is a CSS custom property defined once in `src/styles/app.css`, redefined only inside
the dark-mode blocks. Components reference tokens (`bg-surface`, `text-muted-foreground`, ...)
exclusively — no literal colors, no `text-white`, no hex codes outside `app.css` itself. Dark mode
follows system preference by default and can be pinned by toggling a `.dark`/`.light` class on
`<html>`; the inline script in `routes/__root.tsx` (`lib/theme-script.ts`) applies it before first
paint to avoid a flash.

## Commands

```bash
npm run dev              # vite dev, port 3000
npm run build             # production build (Node/Vercel target — Nitro auto-detects Vercel)
npm run build:cloudflare  # same build, targeting Cloudflare Workers (NITRO_PRESET=cloudflare-module)
npm run start              # node .output/server/index.mjs — what a Modal sandbox runs
npm run typecheck
npm run lint
```

## Deploying

TanStack Start's own build produces a bare fetch-handler with nothing that listens on a port.
The `nitro()` plugin in `vite.config.ts` is what turns that into a real, deployable server —
Nitro picks the output shape from the `NITRO_PRESET` env var, so the same source deploys to:

- **Any Node host / the Modal sandbox itself** — `npm run build && npm run start` (preset
  `node-server`, the default). This is what the sandbox always runs regardless of where the
  project later deploys.
- **Vercel** — zero config; Vercel's own build system detects TanStack Start and drives Nitro's
  `vercel` preset itself.
- **Cloudflare Workers** — `npm run build:cloudflare` (sets `NITRO_PRESET=cloudflare-module`),
  then `npm run deploy:cloudflare`. Nitro generates the real, deployable Wrangler config at
  `.output/server/wrangler.json` (assets binding, bundling rules, `main` — don't hand-edit those);
  the root `wrangler.jsonc` only supplies defaults (name, compatibility date/flags) that Nitro
  reads in.

## The Modal image

Pushing a `v*` tag triggers `.github/workflows/publish-image.yml`, which builds a Modal container
image from this exact commit and records it in `image.json` at the repo root:

```json
{ "imageId": "im-...", "tag": "v1.0.0", "builtAt": "2026-..." }
```

The build itself (`scripts/build-modal-image.ts`) starts from `node:22-slim`, `git clone`s this
repo at the pushed tag (no local-context `COPY` — the Modal JS SDK doesn't support it), runs
`npm ci`, then `npm run build` once just to warm Vite's dep-optimizer cache before discarding the
build output — the sandbox always runs `npm run dev`, never this build.

There's no `images.fromName()`/`.publish()` in the Modal JS SDK — `.build(app)` returns an opaque
`imageId` that only this repo's `image.json` remembers, which is why the workflow commits it back
to `main` as its last step. `apps/api` (in `joddai-monorepo`) reads that file to know which image
to hand `modal.images.fromId(...)` when creating a sandbox — see `plans/01-sandbox-modal.md` Step
2 there for the full mechanism.

Needs `MODAL_TOKEN_ID` / `MODAL_TOKEN_SECRET` set as repo secrets to run.

### Trying the built image locally

`scripts/demo-sandbox.ts` boots a real sandbox from the `imageId` in `image.json`, starts
`npm run dev` inside it, and prints a public tunnel URL — useful for confirming a published image
actually works before wiring it into the main app.

```bash
export MODAL_TOKEN_ID=ak-...
export MODAL_TOKEN_SECRET=as-...
npm install --no-save modal@0.10.0 tsx@4.23.13
npx tsx scripts/demo-sandbox.ts
```

Ctrl+C terminates the sandbox; otherwise it auto-terminates after 15 minutes.

## What's intentionally not here yet

- `src/lib/__builder__/*` — the dev-only console/network capture bridge and the visual-edit
  element picker/tagger. These depend on specs from `plans/07-preview-and-runtime-feedback.md` and
  `plans/08-visual-edits.md` that don't exist yet. Adding stubs now would just be dead weight the
  agent has to read on every run.

## Versioning

Bump `TEMPLATE_VERSION` in `src/lib/constants.ts` on any change that could affect a generated
app's behavior (new dependency, route structure, token names). It's recorded per-project on the
consuming side so a broken app can be traced back to the exact template revision. Tag a release
(`git tag v1.x.x && git push --tags`) to publish a matching Modal image.
